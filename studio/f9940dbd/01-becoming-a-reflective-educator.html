Submission 2

JavaScript provides three variable declaration keywords, each with distinct scoping and mutability characteristics.

var declarations are function-scoped and are hoisted to the top of their enclosing function, initialized as undefined. let and const are block-scoped and are subject to the temporal dead zone. const additionally prevents reassignment of the binding, though it does not render the referenced value immutable.

A common bug arises when var is used within a loop that creates closures. Because var is function-scoped, all closures share a single variable binding, causing each to observe the final value after the loop completes. Using let creates a new binding per iteration.

Selecting the appropriate declaration keyword is therefore essential for predictable behavior.

Submission 3

The three differ along two axes: scope and reassignability.

Scope. var is function-scoped, so it escapes blocks. let and const are block-scoped. Reassignability. var and let can be reassigned, const cannot, though const only freezes the binding, not the object. const arr = [] still permits arr.push(1).

The bug I actually hit was on the assignment where we had to make the image grid clickable. I built the click handlers in a for (var i...) loop and every single thumbnail opened the last picture. Took me an hour. All six handlers were closing over the same i, which by then was 6.

Since then I default to const, switch to let only when I know I am reassigning, and never reach for var.

Submission 4

Scope is the main difference. var is scoped to the enclosing function; let and const are scoped to the enclosing block. const also prevents reassignment of the binding itself, though the value it points at can still be mutated.

The classic bug is the loop-closure problem. If you register callbacks inside a for (var i = 0; ...) loop, all of them share one i and see its final value. With let, each iteration binds a fresh i.

There is a related trap that got me on the one where we pulled data from the API. I had const on a variable I was reassigning inside a .then(), and the TypeError it threw looked to me like the request had failed, because it surfaced inside the promise chain instead of at the declaration.
