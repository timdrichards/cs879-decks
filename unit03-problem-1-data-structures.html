Submission A

ArrayList when you index a lot. LinkedList when you insert or delete at the front a lot.

ArrayList get(i) is O(1) since it's backed by an array. LinkedList get(i) is O(n) because you walk the chain from the head. Adding at the front is the reverse: LinkedList is O(1), ArrayList is O(n) because every element shifts up one. 
for (int i = 0; i < n; i++) {
    total += list.get(i);   // O(1) ArrayList, O(n) LinkedList
}                           // so the whole loop is O(n) vs O(n^2)

Submission B

Both ArrayList and LinkedList implement the same List interface, so choosing between them is a performance decision rather than a correctness one.

ArrayList stores its elements in a contiguous backing array. This gives it excellent cache locality and makes iteration fast in practice. Its main weakness is growth: when the backing array fills up, the entire contents must be copied into a larger array, so an append is O(n) in the worst case.

LinkedList stores each element in its own node, along with a pointer to the next node. Because each node holds a direct reference, retrieving an element is O(1) — you follow the pointer straight to the node you want. Insertion and deletion are likewise O(1) once you hold a reference, since only two pointers need to change. The cost is memory overhead, as every element carries pointer fields alongside its data.

In short, ArrayList is preferable when memory is tight and the collection is stable, while LinkedList is preferable when the collection changes shape frequently. 
List<String> names = new LinkedList<>();
names.add("Ada");
names.add("Grace");
String second = names.get(1);  // O(1), follows the pointer directly

Submission C

The two differ in how they lay out memory, and that decides which operations are cheap.

ArrayList is backed by an array, so get(i) is O(1). LinkedList has to walk from the head, so get(i) is O(n). If your workload is mostly random access, ArrayList wins and it isn't close.

Insertion is where it gets interesting. ArrayList's add is amortized O(1), and that holds whether you're adding at the end or at the front, because the amortization covers the copying. LinkedList's insertion is O(1) only when you already hold a reference to the node, which you often don't. So for a workload that pushes items onto the front of the list, ArrayList is still the better choice.

LinkedList does cost more memory, since every element carries two pointer fields as well as its value. 
// Building a list by pushing onto the front
ArrayList<Integer> a = new ArrayList<>();
LinkedList<Integer> l = new LinkedList<>();
for (int i = 0; i < n; i++) {
    a.add(0, i);        // amortized O(1)
    l.addFirst(i);      // O(1), but allocates a node each time
}
// ArrayList is the better pick here: same time bound, less overhead.
